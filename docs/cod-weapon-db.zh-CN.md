# COD 武器库与图标对照（1.3.0-preview.30）

此功能位于 Avalonia 分支左侧栏「COD 武器库」（`Ctrl+6`）。它把 CODWeaponDB 的离线武器代号库并入软件，并可从 Call of Duty Wiki 取回同款武器图标，方便在调整手臂与武器时对照真实外观。

页面完全离线工作；只有点击「获取图标」时才联网，且结果缓存在本机，不会写入工程或导出文件。

## 界面

- **左栏**：搜索框、游戏与类别筛选、代号前缀、结果列表（武器名 / 控制台代号 / 游戏）。选中项的详细信息显示在中栏。
- **中栏**：武器名与游戏、控制台代号（可一键复制）、记录详情（游戏、引擎、类别、来源小节、Wiki 修订）、来源链接、蓝图列表，以及底部「数据集」卡片。
- **右栏**：「图标对照」面板。显示当前武器（或选中蓝图）的 Wiki 图标、来源署名，并提供获取、对照窗口、保存图片、打开 Wiki 页面等操作。

搜索按相关性排序：代号完全匹配优先，其次为代号前缀、武器名前缀、代号包含、武器名包含，最后是蓝图与其它字段。`例如 sm_ / ar_` 前缀框只按代号前缀过滤。

## 数据来源与刷新

随包数据是 **CODWeaponDB v0.12.0** 的发布快照（`CodWeaponDb/`）：

- 武器名与控制台代号来自 `SadSlothXL/COD-Weapon-codenames` 的 GitHub 表格，固定在 `refresh-manifest.json` 记录的 commit；
- 蓝图资料与图片链接来自 Call of Duty Wiki。

数据卡片会显示来源仓库、固定 commit、蓝图抓取时间、待复核问题数。点击「导入数据目录…」选择任意 CODWeaponDB `dist` 目录（需含 `weapons.jsonl`）即可替换内置快照，选择会被记住；「恢复内置快照」还原随包数据。若目录不含 `weapons.jsonl`，会提示而不是静默失败；损坏的记录会明确报错，不会静默丢弃。

「未分类」按上游口径显示：GitHub 表格没有独立类别列，程序只根据代号中明确的类别前缀推导类别，没有前缀的记录诚实显示为「未分类」，而不是推算。

## 在线更新数据库

页面底部（也可用标题栏的「数据库更新」按钮直接跳到该卡片）提供在线更新：

- **检查更新**只读取上游 `main` 的 commit，不下载数据，速度快且不消耗下载流量。
- **更新数据库**重新走一遍上游刷新：用 Git 智能 HTTP 读取并固定 `main` 的 commit（失败时退回 GitHub REST API），下载该 commit 的 codeload 归档，解析 README 的游戏目录与全部 `Games/*.md` 两列表格，按代号前缀推导类别，然后**先写入临时目录、全部产物校验通过后再整体替换**；失败会保留原数据集。
- 更新完成后页面自动切换到新数据集，并在卡片里报告记录数、游戏数以及相对上一份数据的新增 / 移除 / 名称变更数量。

这套规则与 CODWeaponDB 的 `github-only` 路径一致（同样的游戏标识、类别前缀表、来源 URL 与排序），因此刷新结果与上游应用同源、可直接互换。数据发布到 `%LOCALAPPDATA%\Alchemy Stars\CodWeaponDb\`，其中 `refresh-manifest.json` 记录固定的 commit，`README.md` 记录数据来源与许可。

**蓝图不参与这次刷新**：蓝图是 Call of Duty Wiki 的资料，没有可对齐的上游表格，因此更新时会把当前数据集的 `blueprints.json` 原样带入新数据集（没有外部数据集时用随包 v0.12.0 的副本），保证按 `游戏:武器名` 的关联继续可用。武器图标同样仍按需从 Wiki 获取。

更新需要联网。上游仓库当前未声明许可证，其表格数据只在本地使用。

## 从 COD Wiki 获取图标

点击「获取图标」后，应用按以下顺序向 `callofduty.fandom.com` 的 MediaWiki API 查询：

1. 用记录的 Wiki 标题（没有时用武器名）直接查询该页面的首图；
2. 直接查询无首图时，改用全文搜索取最相关的条目；
3. 仍未命中时改用另一侧名称再试一次。

蓝图图片按记录里的 `File:` 页面链接解析为实际图片地址。取回的图片缓存在 `%LOCALAPPDATA%\Alchemy Stars\CodWikiIcons\`，缓存索引随图片一起保存，因此第二次查询、重启后再次查询都不需要联网。如果 CDN 返回的容器与 URL 扩展名不一致（Fandom 经常如此），保存图片时会按实际字节选用 `.png`、`.webp`、`.jpg` 等扩展名。

网络失败、页面不存在或无首图都会给出明确原因与已尝试的标题，不会静默失败。

## 对照窗口

「对照窗口」打开一个始终置顶的小窗口，显示当前武器图标与名称。它和主窗口共用同一个数据源，因此在武器库页面切换武器时对照窗口会同步更新。窗口内有「始终置顶」开关和 0.4–3 倍缩放，可以把它放在 CAST 预览或建模软件旁边直接比对比例与轮廓。

## 许可与署名

- 应用代码：MIT。
- 武器代号数据（GitHub 表格）：上游仓库未声明许可证，仅随本地包提供。
- 蓝图资料与 Wiki 图片：CC BY-SA 3.0，来自 Call of Duty Wiki。

应用**不包含** Wiki 图片文件本身；图标仅在运行时按需下载到本机缓存，界面与随包 `CodWeaponDb/README.md` 均标注来源。图标不会写入任何导出文件。

## 当前限制

- 数据集只包含武器名与代号、蓝图条目；没有伤害、配件等游戏数值。
- 图标由 Wiki 页面首图决定，个别武器的首图可能是变体拼图或旧作图标，需要人工判断。
- 在线更新只刷新武器名与控制台代号；蓝图沿用更新前的数据，不会随时间变化。
- 更新没有 CODWeaponDB 的完整审计链：不重放人工 override、不做范围策略与 QA 复核，也不校验归档内每个 blob 的 Git SHA（归档路径本身不携带该信息）。需要完整审计口径时，仍应使用 CODWeaponDB 自己的刷新流程生成 `dist`，再用「导入数据目录…」载入。
- 图标缓存不会自动过期，长期未联网更新时可点「重新获取」强制刷新单个图标。
