# 双持动画工作流（1.3.0-preview.13）

此功能位于 Avalonia 分支的左侧「双持动画」栏目。目前实现挂点模式：一份手臂模型、一份单持武器模型、两个独立动画任务，生成两把武器实例和统一骨架。所有计算在 Alchemy Stars 中完成；CAST 合成与预览不需要启动 Blender 或 Maya。

列表与预览之间、预览与右侧属性之间均可拖动分隔条调整宽度。分隔条获得焦点后也可用左右方向键调整；「恢复布局」可恢复默认宽度。缩小窗口时会自动限制侧栏宽度，保留预览空间。

## 使用步骤

1. 在「模型部件」中添加手臂和单个武器模型，分别选择对应部件类型。
2. 在「动画」中添加左右源动画。分别编辑姿势文件、IK、动画层类型和偏移。
3. 打开「双持动画」，新建任务并选择左、右来源。也可以点击「配对已有动画」：按相同文件名前缀以及 `_l_`、`_r_` 后的相同动作名配对。缺侧和重复来源会提示，不会猜测配对。
4. 默认左挂点 `tag_weapon_left`，右挂点 `tag_weapon_right`，源动作挂点 `tag_weapon`。这些骨骼必须存在于手臂骨架中，可以修改名称。
5. 点击「合成预览」。可旋转查看、播放、逐帧查看。修改来源、层、模型或双持配置后，预览会清空，需重新生成。
6. 右侧「导出武器模型」默认开启。导出时额外生成 `动作名_model.cast`，包含手臂、左右两把武器的全部网格、蒙皮和统一骨架，不含动画。设置随每个任务保存；关闭后只停止生成配套模型文件，已有文件不会删除。双持动画 CAST 与普通动画一样只写动画数据。
7. 设置双持名称和输出目录，点击「导出当前双持」或右侧「导出全部双持任务」。右侧属性区域在小窗口中可以滚动。成功提示会列出动画及配套模型文件。预览不会额外生成模型文件。
8. 保存 `.aprj`。双持任务引用来源任务的持久 ID，修改来源文件路径后仍保留对应关系。含双持任务的工程使用 schema 2；请使用此版本或更新版本打开。

要在 Blender/Maya 中分开使用模型与动画，先导入 `_model.cast`，选中新导入的骨架，再导入「仅动画 CAST」输出。SMD/SEAnim 动画也会生成相同的配套 CAST 模型；导入这些动画需要对应 DCC 导入器。配套模型保留原有材质引用，不会补生成缺失的贴图。

## 计算顺序

每侧先复用普通动画管线，独立处理源动画、姿势、叠加层与 IK，并烘焙临时结果。再取左侧手臂链和右侧手臂链，公共骨骼使用右侧结果。当前左侧命名识别沿用 COD 的 `_le` / `_left` 规则；其他命名体系需要新增明确的骨骼分区规则。

武器骨骼分别命名为 `原名__left`、`原名__right`；两份网格的蒙皮索引同步重映射。武器内部机构动画来自各自来源；每份武器根保留模型的绑定局部变换，不重复应用源动画根曲线。每帧分别求解：

```text
输出挂点局部变换 = 输出挂点父骨骼世界变换的逆 × 对应源动作挂点世界变换
输出武器根世界变换 = 输出挂点世界变换 × 武器根绑定局部变换
```

这与 dual 脚本挂点模式的目标一致，但同时求解左右挂点，避免假定左挂点天然对齐。最终结果是一个模型节点、一套连通骨架、一个绝对局部动画；事件以 `left/`、`right/` 区分来源。

双持始终烘焙全骨骼，普通动画的「仅烘焙相关骨骼」选项不缩减双持结果。动画和模型分开输出；SMD、SEAnim 沿用动画输出路径，需要模型时使用双持任务的配套 CAST。

## Blender 与 Maya

Blender 4.3.0 是本次验收基线。FBX 自动检测优先选择 Blender 4.3，随后其他已安装 Blender，未找到 Blender 时使用已有 Maya 路径。也可在启动程序前设置环境变量：

```powershell
$env:ALCHEMY_STARS_FBX_BACKEND = 'blender' # auto / blender / maya
$env:ALCHEMY_STARS_BLENDER = 'C:\Program Files\Blender Foundation\Blender 4.3\blender.exe'
```

FBX 转换在独立后台进程中进行，不安装插件到用户配置，不修改当前 DCC 场景。发布目录包含 `Converters`、`BlenderPlugin` 和 `MayaPlugin`，请保留它们。

如需手动导入 CAST，可将 `BlenderPlugin/io_scene_cast` 打包为 zip 后安装。本项目随附的官方 CAST 插件适配了完整场景的动画绑定，并将骨骼显示长度从 0.0025 调为 1 个源单位，以减少大坐标下的方向精度损失；骨骼头位置及动画变换不变。导入已烘焙结果时关闭插件的 IK 和约束导入，避免重复求解。Blender CAST 导入保留 DQS；FBX 的蒙皮结果可能与 CAST/DQS 不同，建议 Blender 编辑优先使用 CAST 或保存的 `.blend`。

**FBX 精度限制：** 后台转换和结构回读已成功，但 fire 动画的严格回读姿态检查尚未通过。测得武器根最大位置差约 0.0081 个源单位，远处辅助骨骼最大约 0.4581 个源单位。此差异出现在 CAST 导入之后的 FBX 往返过程；不能把 FBX 视为与 CAST 完全等价的已验收结果。`blender/verify_fbx.py` 保留严格检查及失败退出码，供继续修正；本次可靠交付与 Blender 编辑基线使用 CAST / `.blend`。

Maya 原有 CAST/FBX 通道保留。本机没有 Maya，本次没有实际运行 Maya 验收。

## 当前约束与验收

- 每个输入文件恰好一个模型节点；部件必须是一份手臂和一份武器。不支持预先合并了两把武器的模型模式。
- 左右源任务和叠加层帧率必须一致，处理后的总帧数必须一致。本版不自动重采样或自动补齐短侧。
- 要求单位绑定缩放；检测到缩放动画会拒绝。旧版 COD 坐标兼容需关闭。
- 找不到的源曲线会列出名称。Scarab 的 `j_gun1613684` 在所选模型中没有对应骨骼，因此忽略并提示。
- 输出不能覆盖工程引用的源素材。每个输出文件采用临时文件完成后替换；批量任务失败时，此前成功的文件会保留。

Scarab 的 9 对动画（fire、idle、inspect、melee_hit_01、raise、raise_first、reload、reload_empty、run）各产生 221 骨骼、39 网格，帧数分别为 59、231、205、46、30、49、76、76、73，均为 30 FPS。测试覆盖每帧左右武器根的世界变换、左侧叠加传播及右侧隔离、工程引用往返、帧率/帧数错误、源文件保护和仅动画输出。

Blender 验证脚本对全部骨骼全部帧比较 CAST 与实际姿态，位置容差为 `0.0002 + 0.000002 × 世界位置长度`，旋转容差为 `1 - |四元数点积| <= 0.00001`，以容纳远处辅助骨骼的单精度误差。Scarab 的原始贴图路径在本机不存在，几何与动画可验收，材质目前使用缺图占位。
